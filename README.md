# DoL 版本启动器

把多个版本的 Degrees of Lewdity（DoL）放在一起管理，每个版本都有自己的 `mods` 目录、自己的存档与模组开关，互不干扰 —— 类似 PCL 的版本隔离。

自带图形界面（WPF，`DoLLauncher.exe`），不依赖 Python，也不需要装 .NET 运行时（发布版是独立单文件）。

## 界面能做什么

| 功能 | 说明 |
| --- | --- |
| 版本列表 | 自动扫描 `versions/`，显示游戏版本、端口、运行状态；卡片式布局 |
| 启动 / 停止 | 点一下就起内置本地服务器并打开浏览器；换端口自动处理 |
| 添加版本 | 选择任意一个含 `Degrees of Lewdity.html` 的目录，复制进 `versions/` |
| 模组启停 | 勾选即启用，立即重写 `modList.json` |
| 模组排序 | `↑` `↓` 调整加载顺序，越靠前越先加载 |
| 模组导入 / 详情 | 按钮或直接把 zip 拖进列表；详情里可看名称、版本、作者、描述、前置与 README |
| 模组整理 | 重命名、删除；列表会标出同名模组、缺少前置、前置版本不满足等问题 |
| 完整性检查 | 检查本体、`boot.json`、模组依赖、游戏版本、加载顺序是否匹配 |
| 导出版本包 | 生成 `.dolpack`，可勾选「含游戏本体」或只导模组清单 |
| 导入版本包 | 含本体的包 → 新建版本；只含模组的包 → 合并进当前选中版本 |
| 存档助手 | 在游戏同源页面上导出/导入/删除单个存档槽，也可备份到启动器的 `backups` 目录 |
| 备份与诊断 | 存档备份、模组配置导出/还原、整版快照、自动备份开关、兼容性检查与诊断包 |
| 旧 file:// 数据 | 单独列一条伪版本，用来找回旧浏览器里的存档（会提示共享风险） |
| 下载中心 | 本体从汉化仓库 Release 一键下载安装；模组市场按 ModHub 索引一键装到选中版本的 `mods/` |

## 目录结构

```
DoL/
├─ dev/                     ← 源码仓库（git 仓库根目录）
│  ├─ src/DoLLauncher/      ← WPF 启动器源码
│  ├─ tools/                ← 图标生成脚本与中间产物
│  ├─ build.ps1             ← 重新构建 / 打包
│  ├─ README.md
│  ├─ VERIFY.md
│  └─ Vrelicon.png
├─ DoLLauncher/             ← 运行时目录（启动器与游戏版本都在这里）
│  ├─ DoLLauncher.exe       ← 图形启动器（双击即可）
│  ├─ DoL.bat               ← 有 exe 时启动图形界面；带参数时走命令行
│  ├─ launcher.ps1          ← 命令行备用方案（需要 Python）
│  ├─ launcher-versions.json← 自动生成的「版本 ↔ 端口」记录
│  ├─ versions/             ← 所有游戏版本
│  │  └─ 0.5.12.13-v2.101.1/
│  │     ├─ Degrees of Lewdity.html
│  │     ├─ mods/           ← 该版本的模组（丢 zip 进来即可）
│  │     ├─ modList.json    ← 启动器自动生成，不要手改
│  │     └─ mods-state.json ← 启动器记录的启停/顺序，不要手改
│  ├─ backups/              ← 启动器备份（按版本分子目录）
│  └─ logs/launcher.log     ← 启动器运行记录
└─ _archives/               ← 历史发布包 / 旧模组包，不参与运行
```

构建产物会写到 `dev/_publish`，`build.ps1` 会把新的 `DoLLauncher.exe` 自动复制到 `DoLLauncher/` 并覆盖旧文件（覆盖前需要先关掉正在运行的启动器）。

## 快速开始

1. 解压整个压缩包到一个**没有中文和空格**的路径（例如 `D:\Games\DoL`）。
2. 双击 `DoLLauncher.exe`（或 `DoL.bat`）。
3. 左侧选中版本 → 点「启动游戏」。

启动器会在 `127.0.0.1:<端口>` 起一个内置静态服务器，再用默认浏览器打开。服务器窗口不显示，关闭启动器时会询问是否一并停止。

## 版本隔离原理

| 机制 | 效果 |
| --- | --- |
| 每个版本固定一个本地端口（8701、8702…） | 不同端口 = 不同浏览器 origin，所以**存档、模组启用状态、ModHub 设置、游戏设置全部各自独立** |
| 每个版本一个 `versions/<版本>/mods/` 目录 | 模组是磁盘文件，换版本不会串模组 |
| 启动前把 `mods/*.zip` 写成 `modList.json` | DoL ModLoader 自带的 RemoteLoader 会读它，**不需要改 HTML** |

端口分配：首次启动自动分配并写入 `launcher-versions.json`。想重新分配就删掉该文件再启动。

> 注意：浏览器 origin 变了，**旧的 file:// 存档不会自动带过来**，需要用下面的「存档助手」。

## 模组管理

- 安装：点「导入」选 zip，或直接把 zip 拖进列表；包内多套一层文件夹也能自动识别并去掉。
- 卸载：选中后点「删除」，或从 `mods/` 里删掉对应 zip。
- 启停：在启动器里取消勾选即可，会同步写进 `modList.json`，被禁用的模组不加载。
- 排序：`↑` `↓` 调整。默认顺序是 `ModHub → ModI18N → GameOriginalImagePack → 其他`。
- 详情：双击模组或点「详情」，可查看 boot.json 里的名称、版本、作者、描述、前置，以及 README；有主页/WIKI 地址时可直接打开。
- 列表会直接标出同名模组、缺少前置、前置版本不满足；「完整性检查」里还会检查加载顺序。
- **不要用 ModHub 市场再装一份同名牌模组**，否则磁盘一份 + 浏览器存储一份，会重复加载。

## 下载中心

左侧「下载中心」分两页：

- **游戏本体**：从 `Eltirosto/Degrees-of-Lewdity-Chinese-Localization` 的 Release 列表拉取，选一个版本点「下载并安装」。解压到 `versions/<版本号-vModLoader版本>/`，可勾选同时安装 `ModI18N` 汉化模组和 `GameOriginalImagePack` 原版图片包（会直接放进该版本 `mods/`）。
- **模组市场**：索引来自 ModHub 市场（`dol.alseece.top/release-index.json`，失败时自动换备用地址），支持关键词搜索、分类筛选，以及「未安装 / 可更新」筛选。
- 市场会按目标版本的磁盘模组标出「已安装」「可更新」，不用再打开 ModHub 查。
- 安装时会检查前置：缺少或版本过低会自动补装（ModLoader 内置部件不算缺），安装前会列出将要补装的模组。
- 选中模组后可点「加载版本」，从该仓库 Release 列表里选一个历史版本再安装。
- 下载时会到模组对应的 GitHub 仓库 Release 解析 zip，写入「安装到版本」选中的版本 `mods/` 并自动重建 `modList.json`。
- 下载与安装过程都会写进「运行记录」，失败原因也会打印在那里。

> 市场索引只收录 GitHub 上还能取到的模组；如果某个模组在 GitHub 上没有 zip 资产，会在日志里提示「没有找到模组 zip」。

## 导出版本包（.dolpack）

给别人分发时用「导出版本包」：

- **含游戏本体**：包里带 `game/`（HTML + LICENSE 等）和 `mods/`，对方导入后直接多出一个可启动的版本。
- **只导模组清单**：包里只有 `manifest.json` + `mods/`，对方在启动器里选中自己的版本后导入，模组会合并进去（同名覆盖，启停状态和顺序一起带过去）。

`.dolpack` 本质是 zip，改后缀为 `.zip` 也能用普通解压工具查看；manifest.json 记录了版本号、游戏版本、模组清单和备注。

## 存档导入导出

存档保存在浏览器按 origin（端口）隔离的 IndexedDB（库名 `idb`，表 `saves` / `details`），启动器本身读不到浏览器数据，所以提供了「存档助手」：

1. 选中版本 → 点「存档助手」，会在该版本的同一端口打开一个页面。
2. 「导出全部存档」→ 下载一个 `dol-saves-<版本>-<时间>.json`。
3. 到目标版本打开存档助手，选择该文件 →「导入到当前版本」→ 刷新游戏页面。

注意：

- 导入前**先关掉其它游戏标签页**，否则数据库被占用会失败。
- 导入会覆盖同名存档。
- 换电脑：把导出的 json 拷过去即可。
- 只是重启启动器/服务器，存档还在，不需要迁移。

启动器集成后，存档助手还提供：

- **启动器备份**：点「立即备份到启动器」，存档会写进 `backups/<版本>/saves/`，不经过浏览器下载目录；可在页面里直接还原或删除。
- **单槽管理**：列出每个存档槽，可单独导出/删除；「导入存档槽文件」只覆盖对应槽，不影响其它槽。

## 备份与诊断

左侧「备份与诊断」页把 ModHub 的备份/诊断能力搬进了启动器：

| 功能 | 说明 |
| --- | --- |
| 立即备份存档 | 打开同源的自动备份页，把浏览器存档写进 `backups/<版本>/saves/` |
| 导出 / 还原模组配置 | 保存模组顺序与启停，换版本或误操作后可一键还原 |
| 创建整版快照 | 只含模组与配置，或勾选「包含游戏本体」；快照在还原时可作为新版本导入 |
| 自动备份 | 开关可关；启动时按间隔自动建快照，并按「保留份数」清理旧快照 |
| 自动备份存档 | 开关可关；启动游戏时额外打开一个自动备份页，完成后自动尝试关闭 |
| 兼容性检查 | 列出游戏版本、ModLoader 版本、每个模组的版本/前置/加载顺序问题 |
| 导出诊断包 | 打成一个 zip：检查报告、模组清单、boot.json、启动器日志、游戏日志（如果目录里有） |
| 日志 | 查看启动器运行记录，或选择 ModLoader 导出的日志文件载入查看 |

> 浏览器存档只能通过同源页面读写，所以「立即备份存档」会短暂打开一个页面；这是为了不污染游戏目录，也避免把压缩包下载到本地。

## 旧 file:// 数据

早期直接把 HTML 用 `file://` 打开产生的存档，浏览器会把它们视作同一个来源。启动器把它列成一条「旧版 file:// 数据」伪版本：

- 点「用 file:// 打开」会先弹共享风险提示；
- 打开后进游戏「存档 → 导出」，再到正式版本（有端口的）里「导入」；
- 迁移完成后就不需要再用它了。

## 命令行用法（备用）

`launcher.ps1` 保留作无图形界面时的后备方案，**需要 Python 3 在 PATH 中**（只用来起静态服务器）：

```
DoL.bat              → 菜单（含「0) 停止所有正在运行的版本」）
DoL.bat 0.5.12.13    → 直接启动指定版本
DoL.bat -List        → 列出所有版本、端口、mods 数量
DoL.bat -Stop        → 停止所有由本启动器拉起的服务器
```

> 图形版启动器不需要 Python；`DoL.bat` 无参数时会优先启动图形版。

## 常见问题

**1. ModHub 显示「已安装模组 0 个」**

正常。ModHub 只统计它自己导入到浏览器存储里的模组；本方案的模组是磁盘 `mods/` 加载的旁加载模组，不在它的统计里。要看真实加载情况：游戏里按 `Alt+M` 打开 ModLoader 模组管理，应能看到 `[Remote] ModHub / ModI18N / GameOriginalImagePack`。

**2. 日志警告 `[GameOriginalImagePack] imageGetter cannot find img ... wolfharmony.png`**

官方图片包自身的缺图（新包把 wolf 系列改名成 `sym-*`，旧名文件没带），只影响一个装饰图标，可以忽略。

**3. 提示端口被占用 / 版本显示「运行中」但打不开**

在启动器里点「停止」，或执行 `DoL.bat -Stop`，然后重新启动。启动器遇到端口冲突会自动换一个空闲端口。

**4. 页面空白或一直加载**

刷新页面；确认启动器还开着（服务器跟着启动器进程一起退出）。

**5. 移动 / 重命名版本文件夹失败**

该版本服务器还在运行（目录被占用）。先停止再移动。

**6. 提示缺少 .NET 运行时**

说明拿到的是 framework-dependent 版本。换成自带的独立单文件 exe，或安装 .NET 10 桌面运行时。

**7. 导入包时提示「这个包不含游戏本体」**

这是「只导模组清单」的包。先在左侧选中要接收模组的版本，再导入。

## 自行构建

需要 .NET 10 SDK：

```
.\build.ps1                  # 生成 DoLLauncher.exe + 只有启动器的分发包
.\build.ps1 -IncludeVersions # 连本机 versions 一起打进分发包（体积很大）
.\build.ps1 -NoZip           # 只生成 exe
```

构建产物会复制到项目根目录的 `DoLLauncher.exe`，分发包输出到上一级目录的 `DoL-Launcher.zip`。

开发者可用 `DoLLauncher.exe --selftest` 跑一次自检，结果写入 `self-test.log`（检查版本扫描、内置服务器、modList、存档助手页、.dolpack 往返）。

# 剧情分支思维导图调研（需求 12）

> 目标：先确认「玩家经历过的事件与分支」在存档/游戏数据里是否可得，再决定是否实现思维导图页面。
> 本轮结论落点为：**数据部分可得，可做“已发生路径”，但“未选择分支 + 角色/地点/图标映射”需要 Mod 补充**。因此本轮只预留接口，不新增未验证的界面。

## 1. 调研样本与方法

- 样本：`DoLLauncher\backups\0.5.12.13-v2.101.1\saves\auto-saves-20261108-145704.json`（约 76 MB，`dol-saves/1` 整库导出）。
- 方法：直接检查导出 JSON 的 `dbs[].stores[].records`，并在游戏存档写入链路（`SaveHelperPage.cs`、`IdbMirrorStore`）中核对库表名。
- 存档实际位置：浏览器 IndexedDB 库 **`degrees-of-lewdity`**，表 **`saves`**（keyPath `slot`）与 **`details`**（keyPath `slot`）。
- 启动器落盘镜像：`versions\<版本>\data\idb-mirror.json`（`IdbMirrorStore`，同样使用 `dol-saves/1` 整库格式），备份文件为 `backups\<版本>\saves\saves-*.json`（`dol-saves/1`）。

## 3. 数据可得性结论

| 数据项 | 来源 | 可得性 | 说明 |
| --- | --- | --- | --- |
| 已访问段落 / 章节标题 | `saves[].data.history[].title` | ✅ 可得 | 英文 passage 名（如 `Bedroom`），按访问顺序排列 |
| 各步骤的变量快照 | `saves[].data.history[].variables` | ✅ 可得 | 包含时间、天气、NPC 关系/事件标记等大量字段 |
| 存档名称 / 时间 / 摘要 | `details[].data.title`、`date`、`metadata.saveName` | ✅ 可得 | 可作为思维导图根节点与存档选择器 |
| 角色 / 地点 / 特殊事件的分类 | 无显式字段 | ⚠️ 需映射 | 需要 passage → 角色/地点/事件类型的规则表，或 Mod 写入标签 |
| 未选择的选项 / 分支走向 | 无 | ❌ 不可得 | SugarCube history 只记录已发生的路径，不记录被放弃的选项 |
| 节点图标 / 立绘 | 游戏与模组美术资源 | ⚠️ 需映射 | 需要资源索引表；直接扫描游戏目录不可靠（模组可覆盖同名资源） |
| 完整历史长度 | `history` 数组 | ⚠️ 受限制 | SugarCube 的 moment 历史有上限，只能覆盖最近若干步；更早路径需 Mod 记录 |

**结论**：可以做“玩家已经走过的事件路径”思维导图（节点来自 `history[].title`，分组来自规则表），但无法仅靠原版存档还原“所有可选分支”。若必须展示分支树，需要 Mod 在游戏内记录每次选择（选择前选项列表 + 选择结果），再由启动器读取。

## 4. 实现方案

### 4.1 启动器内置（推荐先做“已发生路径”）

1. 数据读取：优先读 `versions\<版本>\data\idb-mirror.json`，没有镜像时读 `backups\<版本>\saves\saves-*.json`；都不可用时提示“先启动一次游戏完成数据落盘”。
2. 解析：只提取 `details` 的显示信息与 `saves[].data.history[].title / variables`，不整份反序列化到内存（样本 76 MB，需流式或按库表读取）。
3. 映射规则表：`passage → { 角色, 地点, 事件类型, 图标资源 }`，放在 `skins` 同级的可编辑 JSON 中，允许用户/Mod 补充。
4. 展示：树/思维导图按时间顺序展开，支持按角色、地点、特殊事件筛选；点击节点显示该步骤的变量摘要。
5. 图标：先用内置占位图标；资源索引完成后复用游戏与模组美术资源。

### 4.2 独立 Mod（后续）

- 游戏内左侧新增入口按钮，点击打开同一套思维导图页面；
- Mod 记录每次选择（`passage`、选项文本、结果状态），写入独立 IndexedDB 库；
- 启动器读取该库时与 `history` 合并，形成真正的分支树；
- 入口与数据格式由 Mod 自行维护，启动器只做只读展示。

## 5. 本轮已落地

- 新增 `Core\Story\StorySource.cs`：
  - `IStorySource`：约定“是否可用 / 不可用原因 / 读取最近存档路径”；
  - `StoryPath` / `StoryStep`：只保留标题与少量关注变量，避免大存档占内存。
- 未新增导航页，避免在映射数据缺失时展示假数据；后续接入解析器与规则表后，再在 UI 层加“剧情”页。

## 6. 风险与后续

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| 大存档解析卡顿 | 镜像可能几十 MB | 流式读取 + 后台线程 + 只保留必要字段 |
| history 长度有限 | 只能看到最近若干步 | 在报告中明确说明；完整路径依赖 Mod |
| passage 名称不稳定 | 游戏/模组改名会导致映射失效 | 规则表按“精确匹配 + 关键词兜底”设计，缺失时归入“未分类” |
| 图标资源版权与覆盖 | 模组可能替换同名资源 | 只读取用户本地资源，不随启动器分发 |
| 与美化包/主题冲突 | 思维导图配色需跟随主题 | 节点颜色全部走 `DynamicResource`，不硬编码 |

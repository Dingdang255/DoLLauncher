# 玩家头像自动生成调研（需求 16 附）

> 需求原文：支持从指定存档中自动提取角色状态并生成头像；支持用户手动上传自定义头像。
> 本轮落地：手动上传已完成；自动生成先调研并预留接口，界面暂用内置占位图。

## 1. 调研范围

- 存档库：IndexedDB `degrees-of-lewdity`，表 `saves` / `details`（与剧情分支调研同一份样本）。
- 关注字段：`saves[].data.variables` 中与角色外观 / 立绘 / 头像相关的键；`details[].data.title` 等摘要信息。

## 2. 结论

| 需求 | 数据可得性 | 说明 |
| --- | --- | --- |
| 角色身份 / 姓名 | ⚠️ 部分可得 | `variables` 中有姓名、性别、体型等状态，但不同版本键名会变化 |
| 角色外观（发色、瞳色、服装等） | ⚠️ 部分可得 | 有零散的外观变量，但没有统一的“外观快照”字段 |
| 角色立绘 / 头像图片 | ❌ 不可得 | 存档只存状态，不存图片；游戏立绘由运行时资源与 Mod 决定 |
| 场景 / 时间 | ✅ 可得 | `timeStamp`、`weatherObj` 等可用于生成文字摘要 |

**结论**：仅靠原版存档无法稳定生成“角色头像图片”。要做自动头像，需要：

1. 一份按游戏版本维护的“变量 → 外观合成规则”，从发型 / 发色 / 瞳色等变量绘制头像；或
2. 由 Mod 在游戏中导出角色立绘 / 头像到磁盘，启动器只负责读取。

在上述数据补齐前，强行生成会出现“同一个人不同版本头像不一致”或“只有纯色块”的假数据，因此本轮不实现。

## 3. 本轮已预留

- `Core\Ui\AvatarRules.cs` 中的 `IAvatarSource`：
  - `IsAvailable` / `UnavailableReason` 供设置页判断是否显示「从存档生成」；
  - `TryCreateAsync(versionFolder, outputPath)` 约定生成结果写入启动器管理的头像目录。
- 当前默认实现为空（不注册），手动上传路径已完整可用；后续接入外观规则或 Mod 导出的头像后，只需实现接口并在 `LoadPlayerAvatar` 中优先尝试。

## 4. 后续建议

- 优先与剧情 Mod 共用“存档解析”模块，避免两套变量读取逻辑。
- 生成头像时输出到 `user\generated-avatar.png`，不要覆盖用户手动上传的 `user\avatar.*`。
- 增加“预览后确认”步骤，避免自动生成结果直接替换用户头像。

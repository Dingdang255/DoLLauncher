## 1. 入门与基础

### Q1. DoLL 启动器是什么？能做什么？

它是 *Degrees of Lewdity*（DoL）的多版本管理器，主要解决三件事：

- **多版本隔离**：每个版本分配独立本地端口（`127.0.0.1:8701~8899`），浏览器按 origin 隔离存档，换版本不会串档。
- **模组管理**：安装、启停、排序、检查冲突，自动生成 ModLoader 读取的 `modList.json`。
- **配套工具**：存档助手、备份/快照、剧情分支模拟、下载中心（游戏本体 / 模组市场 / Lyra 整合包）、诊断、UI 美化包。

### Q2. 桌面端和 Android 端有什么区别？

| 能力 | Windows 桌面端 | Android 端 |
| --- | --- | --- |
| 游戏载体 | 系统浏览器独立窗口 / 独立配置 | 应用内 WebView |
| 版本隔离 | 按端口隔离 | 按端口隔离 |
| 同时运行 | 不同版本可分别启动 | 同一时间只保留一个游戏画面，切换版本会替换旧实例 |
| 添加已有版本目录 | 支持（选择文件夹后整目录复制） | 不支持目录树选择，请导入 zip |
| 关闭游戏页面 | 关闭浏览器窗口 | 返回启动器只隐藏画面，游戏继续运行；需在版本页或通知里停止 |

### Q3. 第一次使用应该怎么开始？

1. 打开「下载中心 → 游戏本体」，选一个版本安装。
2. 回到「版本管理」，点版本进入详情，先点「问题检查」。
3. 点「启动」，首次启动会创建该版本的独立浏览器数据。
4. 需要模组时，进「模组管理」从市场安装，或导入模组 zip。

### Q4. 启动器会修改游戏本体或存档吗？

- 启动器不会改写游戏 HTML 本体，主要做三件事：启动本地静态服务器、生成/更新 `modList.json`、读写浏览器数据。
- 模组启停、排序、完整性检查会改写 `mods/modList.json` 等配置，不改游戏 HTML。
- 清空 Mod 缓存、删除版本、还原备份属于破坏性操作，执行前都会有确认提示。

## 2. 安装与更新

### Q5. Android 端怎么安装？提示「未知来源」怎么办？

下载 `DoL-Launcher-android.apk` 后直接安装。若系统拦截：

1. 在提示中选「设置」→ 允许该来源安装未知应用；
2. 或到 系统设置 → 应用 → 特殊权限 → 安装未知应用，允许文件管理器/浏览器；
3. 返回继续安装。

### Q6. 启动器怎么更新？会丢数据吗？

- 打开「设置 → 版本信息」或启动时自动检查更新，点「立即更新」会下载 APK 并交给系统安装程序。
- 覆盖安装不会清空启动器数据（版本、存档、模组、备份都在数据目录里）。
- 更新前仍建议在「备份」页做一次备份，尤其是准备跨大版本升级时。

### Q7. 为什么现在启动器 APK 下载变快了？

旧版本 Android 更新是单独直连 GitHub 单连接下载，绕过了模组的测速/镜像/分段下载引擎。现在 APK 与游戏、模组共用同一套下载引擎：

- 「设置 → 网络下载 → 模组下载源」选的线路对 APK 同样生效；
- 选「自动」会先测速，再选最快线路；
- 支持镜像前缀与 Range 分段并发，低速线路会被自动跳过。

### Q8. 支持哪些 Android 版本？

最低 Android 7.0（API 24）。实际体验建议 Android 10 及以上，并保持 **Android System WebView / Chrome** 为较新版本。

### Q9. 更新失败 / 安装包解析失败怎么办？

1. 确认下载完整（重新下载一次）；
2. 确认系统允许安装未知应用；
3. 若提示签名不一致，先卸载旧版再安装（卸载前务必导出/备份数据）；
4. 仍失败时，用浏览器到发布页手动下载 APK。

## 3. 版本管理

### Q10. 怎么导入别人给的游戏版本 / 整合包？

在「版本管理」右上角点「导入」，选择一个 zip 包。导入器会自动识别：

- **版本包**：包内包含游戏 HTML（如 `Degrees of Lewdity.html`，允许根目录或唯一一层子目录），会新建一个版本；
- **模组包**：会让你选择要导入到哪个版本；
- 无法识别的文件会跳过并给出原因。

Lyra 整合包导入后，还会询问是否把内置模组解压到 `mods/`。

### Q11. 为什么 Android 端没有「添加已有文件夹」？

桌面端可以选择一个已存在的版本目录并整目录复制；Android 需要 SAF 目录树授权（`ACTION_OPEN_DOCUMENT_TREE`）才能遍历外部目录，目前未实现。替代方案：

- 把版本目录压成 zip 后导入；
- 或把目录放到启动器数据目录的 `versions/` 下（需要文件管理器有权限）。

### Q12. 为什么每个版本的存档不会互相覆盖？

启动器给每个版本固定一个本地端口，游戏地址是 `http://127.0.0.1:<端口>`。浏览器按「协议 + 主机 + 端口」隔离存储，端口不同就是不同 origin，因此 IndexedDB / localStorage 天然分开。

### Q13. 端口冲突 / 打不开 `127.0.0.1` 怎么办？

- 启动器会在 `8701~8899` 内自动找空闲端口，一般不需要手动处理。
- 如果版本记录的端口被其它程序占用，启动时会自动换端口并更新记录。
- 仍异常时：先停止游戏，再在版本详情点一次「问题检查」，然后重新启动。

### Q14. `file://` 版本和 `http` 版本有什么区别？

- **http 版本**：走启动器内置服务器，功能完整（模组启停、存档助手、缓存清理、诊断采集等）。
- **file:// 版本**：直接把本地 HTML 交给浏览器/WebView 打开，兼容老版本；但受浏览器本地文件限制，部分资源、模组、存档助手可能不可用，Android 上尤其明显。
- 「清空 Mod 缓存」只支持 http 版本。

### Q15. 删除版本会删掉存档吗？

会。删除版本会递归删除该版本目录，包含游戏本体、模组以及该版本的浏览器数据（存档通常在其中）。删除前请：

1. 在「存档助手」或游戏内导出 `.save`；
2. 或在「备份」页创建快照 / 立即备份存档；
3. 确认不再需要该版本。

### Q16. 同一版本重复点「启动」会重新加载吗？

不会。Android 端同一版本会复用已有 WebView 与页面状态，只是把画面切回来；需要重新加载时，在游戏页用「重试/刷新」或先停止再启动。

## 4. 下载中心

### Q17. 游戏本体、汉化、图片包应该怎么选？

下载中心提供两类常见形态：

- **汉化整包**：包含游戏本体与汉化，体积较大，装完即可用；
- **ModLoader Neo 单文件**：只有单个 HTML，需要时再附带汉化（ModI18N）与图片包。

按提示勾选需要的附带内容即可。安装完成后启动器会自动重建 `modList.json`。

### Q18. 下载很慢 / 一直卡在测速怎么办？

1. 打开「设置 → 网络下载」；
2. 「模组下载源」选「自动（测速选最快）」，或手动换一个镜像（GH-Proxy、ModHub 加速等）；
3. 「GitHub 接口源」只影响版本列表/README 等 API 请求，被限流时可切镜像；
4. 镜像都慢时选「GitHub 直连」再试。

下载引擎会按实际收到的字节判断线路是否「假死」，长时间低速会自动换下一条线路。

如果开启了「设置 → 网络下载 → 启动时预取索引」，启动器会在启动后并行预取游戏本体、模组市场与整合包索引；进入下载中心会直接复用预取结果，不会重复请求。预取只提前拉索引，不会加速实际文件下载。

### Q19. 下载能取消吗？

可以。下载中心左侧任务列表里有取消按钮；取消后临时文件会被清理。启动器更新弹窗关闭时也会中断 APK 下载。

取消任务不会再弹出「A task was canceled. / OperationCanceled」失败框，而是提示「任务已取消。」；只有真实的网络或安装错误才会显示具体失败原因。

### Q20. 下载完成但安装很久 / 应用像卡住了？

v1.6.x 起，整包解压、`modList.json` 重建、删除版本目录等重 I/O 已移到后台线程，并显示全页进度遮罩（下载百分比 / 正在解压 / 正在安装附带模组）。

如果仍长时间无响应：

- 确认使用的是最新构建；
- 大整合包解压本身需要时间，等待遮罩文案变化；
- 超过很久仍无变化时，停止应用后查看「诊断 → 启动器日志」。

### Q21. Lyra 整合包是什么？

一种把游戏本体与内置模组打在一起的整合包。启动器能识别其命名并：

- 安装为一个新版本；
- 读取包内内置模组列表；
- 询问是否把普通内置模组解压到 `mods/`（ModLoader 必需组件会保留在内置，不搬出）。

## 5. 模组

### Q22. 模组有哪几种安装方式？

1. **模组市场**：搜索/浏览后直接安装到目标版本；
2. **本地 zip 导入**：在模组管理页导入；
3. **整合包内置**：安装 Lyra 整合包后按提示解压；
4. **分享导入**：从其它应用把 zip 分享给启动器。

### Q23. 模组 zip 有什么格式要求？

- 推荐 zip 根目录直接包含 `boot.json`；
- 或者 zip 内只有一层同名子目录，`boot.json` 在该子目录里（启动器会自动处理）；
- `.modpack` 是 ModLoader 私有格式，启动器无法读取 `boot.json`，只按文件名展示，校验能力有限。

缺少 `boot.json` 或无法解析的包会被跳过，并提示「不是有效的模组」。

### Q24. 启停、排序模组后需要重启游戏吗？

需要让游戏重新读取 `modList.json`。建议：

1. 停止当前游戏；
2. 在模组页完成启停/排序（会自动重建 `modList.json`）；
3. 重新启动。

游戏运行中修改可能不会立即生效，个别文件被占用时启动器会跳过写入，下次重建时再补上。

### Q25. 提示模组冲突 / 缺少前置怎么办？

- 在模组详情里查看作者、版本、前置声明与 README；
- 用「问题检查」或模组页的检查功能查看冲突与缺失项；
- 缺少前置时先安装前置模组，再启用目标模组；
- 两个模组修改同一文件时，加载顺序（排序）通常决定谁生效。

### Q26. Android 上装了大模组后白屏 / 闪退？

Android WebView 渲染进程的 JS 堆上限明显小于桌面浏览器（约 256MB）。启动器会在启用模组体积过大时警告：

- 单个模组约 ≥ 20MB；
- 启用模组总计约 ≥ 40MB。

建议减少同时启用的大模组（如图片包、大型美化），先禁用最近新增的模组，再逐个排查。

### Q27. 「内置模组」解压是什么意思？

Lyra 整合包会把部分模组放在游戏内置位置。解压到 `mods/` 后，它们才会出现在启动器模组列表里，可被启停、排序、替换。ModLoader 必需组件不会被解压，继续保留在内置位置。

### Q28. 删除/停用模组会影响存档吗？

一般不会。存档在浏览器数据里，模组只是读取/写入游戏状态。但个别模组会往存档写自定义字段，删模组后可能出现「未知字段/剧情缺失」，建议先备份再调整模组。

## 6. 存档与备份

### Q29. 存档文件在哪？为什么在 `versions/` 里找不到 `saves`？

DoL 的存档主要保存在浏览器的 IndexedDB / localStorage 中，不是一个可直接双击的 `saves` 文件。启动器通过浏览器配置目录管理它们，所以：

- 想导出：用游戏内存档界面的「导出」得到 `.save`，或用存档助手；
- 想整包备份：用「备份」页的立即备份 / 快照 / 磁盘镜像。

### Q30. 怎么导出 `.save`？

在游戏内存档界面点导出。Android 端 WebView 不支持 `blob` 直接下载，启动器已接管下载，会弹出系统「保存到文件」对话框；取消时缓存副本仍保留在应用缓存目录。

### Q31. 怎么导入 `.save`？

两种方式：

1. **游戏内导入**：进入该版本的存档界面，选择「导入存档」，启动器已接管文件选择器，选 `.save` 即可；
2. **备份还原**：如果之前用「备份」页备份过存档，在备份列表里点还原，启动器会排队在该版本下次启动时导入。

### Q32. 存档助手能做什么？

存档助手是该版本的网页版存档管理界面，可查看槽位、导出存档等。Android 端的导出会走系统保存对话框。它依赖本地服务器，因此 `file://` 版本可能不可用。

### Q33. 「立即备份」「快照」「整版快照」有什么区别？

- **立即备份存档**：备份浏览器存档，不询问备注；
- **创建快照**：备份模组与配置，体积小；
- **整版快照**：额外包含游戏本体，体积大，还原时作为新版本导入，适合完整迁移；
- **自动备份**：启动版本时按设置自动备份，可配置保留份数；
- **磁盘镜像**：把浏览器存档镜像到磁盘，便于查看/复制，也可作为还原来源。

### Q34. 还原备份会覆盖当前存档吗？

会。还原通常在目标版本下次启动时执行，覆盖对应存档数据。还原前建议先对当前状态做一次「立即备份」，避免误覆盖。

### Q35. 换手机 / 换电脑怎么迁移？

推荐按需选择：

- **整包迁移**：复制整个启动器数据目录（见第 10 节），保持 `versions/`、`backups/` 结构不变；
- **按版本迁移**：在版本详情导出 `.dolpack`（可选包含游戏本体/存档），到新设备导入；
- **只迁存档**：导出 `.save` 或备份文件，到新设备还原。

## 7. 剧情分支模拟

### Q36. 剧情页的数据从哪来？

选择「版本 + 存档槽」后，启动器读取该存档的剧情进度，并结合存档里的分支信息生成树。它需要该版本安装并启用 **story-branch-sim（剧情分支模拟）** 模组。

### Q37. 为什么提示缺少剧情模组？

说明当前版本没有启用 `story-branch-sim`。处理方式：

1. 到模组管理安装/启用该模组；
2. 重新启动一次游戏，让模组写入分支数据；
3. 回到剧情页刷新。

### Q38. 「仅成功」和「随机种子」有什么用？

- **仅成功**：只展示成功通过的分支，隐藏失败尝试，图更清爽；
- **随机种子**：固定模拟的随机序列，便于复现同一组结果；
- 模拟期间启动器会打开游戏页面跑数据，完成后展示摘要与分支列表。

### Q39. 导出 JSON 和导出图片有什么区别？为什么有时只能导出 JSON？

- **导出结果（JSON）**：完整分支数据，体积小，任何环境都能用；
- **导出图片（PNG）**：把分支画布绘制成长图，适合分享；
- 图片高度上限约 20000px，超出会等比缩放；如果取不到渲染视图（宽度/高度为 0）或绘制失败，会自动降级导出 JSON 并提示原因。

## 8. 诊断与故障排查

### 通用排查顺序

1. 停止游戏 → 重新启动；
2. 版本详情 → 「问题检查」；
3. 禁用最近新增的模组，再启动；
4. 打开「诊断」看最近游戏日志 / 启动器日志；
5. 仍无法解决时，导出诊断包反馈（见 Q49）。

### Q40. 启动时提示「WebView 版本过低」怎么办？

这是 Android 系统 WebView 内核太旧，游戏/ModLoader 用到了新特性。处理：

1. 到应用商店更新 **Android System WebView**（部分机型是 **Chrome**）；
2. 系统设置 → 应用 → 显示系统应用 → Android System WebView → 若被「停用」则启用；
3. 更新后重启手机；
4. 在启动器「设置 → 版本信息」或「诊断 → 运行环境」里确认 WebView 版本已变化；导出的诊断包 `system.txt` 也会记录该版本。

国产 ROM 若无法单独更新 WebView，通常需要更新系统版本，或换用系统 WebView 较新的设备。桌面端不受此限制（用系统浏览器）。

### Q41. 为什么别人能玩的版本，我这里一进就报错？

按优先级排查：

- **WebView 版本**：见 Q40；
- **游戏版本与模组不匹配**：问题检查里会提示版本差异；
- **模组过大**：见 Q26；
- **file:// 版本限制**：换成 http 版本或让作者提供完整包；
- **存储空间不足**：解压/浏览器数据写入失败。

### Q42. 游戏白屏 / 黑屏 / 闪退怎么办？

1. 回到启动器，确认服务器状态是「运行中」；
2. 禁用大模组，尤其是图片包/美化；
3. 游戏页点「重试」（会重建 WebView）；
4. 查看「诊断 → 最近游戏日志」，搜索 `error` / `fatal`；
5. 仍失败时导出诊断包。

### Q43. 提示「可能存在问题」，还要继续启动吗？

问题检查只是风险提示，不是硬拦截。常见项：

- 游戏版本与模组声明版本不一致；
- 缺少前置模组；
- 模组体积过大；
- 端口/文件异常。

可以查看「问题详情」后决定是否仍然启动；若启动后异常，优先处理其中的错误项。

### Q44. 应用「无响应」/ 卡死怎么办？

- 确认使用最新构建：整包解压、删除版本、重建 `modList` 等重活已移到后台线程，并显示进度遮罩；
- 大整合包解压需要时间，观察遮罩文案是否在变；
- 长时间无变化时，强制停止应用，重启后查看启动器日志；
- 若每次都在同一步卡住，记录步骤并反馈。

### Q45. 日志在哪？

- **启动器日志**：数据目录下 `logs/launcher.log`；
- **游戏日志**：每个版本自己的日志目录，可在诊断页的「最近游戏日志」列表看到文件名与时间；
- Android 端可在「设置 → 版本信息」打开数据根目录后用文件管理器查看。

### Q46. 诊断页的三种长文本怎么看？

「最近游戏日志」「日志分析」「启动器日志」默认只显示末尾摘要，点击文本会打开独立查看界面，可复制/分享完整内容。

### Q47. 「实时诊断」和「手动诊断」有什么区别？

- **手动诊断**：分析最近一次游戏日志，适合事后排查；
- **实时诊断**：每 2 秒统计当前游戏实例的日志级别数量与异常分组，不展示原始日志，适合边玩边看；
- 离开诊断页面会自动停止实时轮询。

### Q48. 「清空 Mod 缓存」会删存档吗？

不会删 `saves/details` 存档，但会删除该版本除存档库以外的 IndexedDB，包括：

- Mod 图片缓存、翻译缓存、模组包缓存；
- Mod 的本地设置与缓存。

操作需要两次确认，登记后在**下次启动该版本时**执行并自动重新加载页面。建议先关闭正在运行的游戏。该功能位于「诊断 → 存储维护」，与桌面端一致。

### Q49. 导出诊断包有什么用？包含什么？

诊断包是一个 zip，通常包含：运行环境（含 WebView 版本）、兼容性检查结果、启动器日志、游戏日志、模组元数据等。反馈问题时附上它能大幅减少来回询问。导出位置由系统「保存到文件」对话框决定，不支持时退回分享面板。

### Q50. 「完整性检查」做什么？

检查版本目录与模组：缺少 HTML、`boot.json` 无法解析、模组缺失前置等，并重新生成 `modList.json`。它不会删除模组或存档，适合在「游戏打不开 / 模组不生效」时先跑一次。

## 9. 界面与美化包

### Q51. 怎么使用 UI 美化包？

「设置 → 界面与外观 → UI 美化包」导入 zip。美化包可替换主色、页面背景、控件样式；格式为 `dolskin/1~3`，样式是 CSS 子集（`skin.css` 或 `skin.json` 的 `android.styleSheet`）。详细规范见 [UI美化包格式.md](UI美化包格式.md)。

### Q52. 导入美化包后没变化 / 提示警告？

- 确认美化包声明的 API 版本与当前启动器兼容；
- 查看「查看警告」里的不支持项（部分 CSS 属性在 Android 端会被忽略）；
- 卸载美化包可恢复默认主题；
- 美化包设置优先于普通主题与主题色。

### Q53. 改主题色 / 头像 / 副标题在哪？

「设置 → 界面与外观」，修改后立即生效。头像支持本地图片；副标题留空可恢复默认。

## 10. 数据位置、迁移与卸载

### Q54. 启动器数据目录在哪？

- **Windows**：`DoLLauncher.exe` 所在目录（含 `versions/` 的根目录）；
- **Android**：`内部存储/Android/media/com.dol.launcher/DoL/`（不同 ROM 可能显示为 `Android/media/...`，可在「设置 → 版本信息 → 打开根目录」确认）。

典型结构：

```
DoL/
├─ versions/                 # 各版本游戏与模组
├─ backups/                  # 备份与快照
├─ logs/                     # 启动器日志
├─ launcher-versions.json    # 版本配置（端口、名称等）
└─ .dol-ports 等隐藏目录      # 缓存/清理标记
```

### Q55. 卸载启动器会删数据吗？

**不要假设数据一定保留。** 卸载前请：

1. 导出需要的 `.save`；
2. 创建快照/备份；
3. 或把整个 `DoL/` 目录复制到别处。

### Q56. 启动器联网做什么？会上传存档吗？

联网主要用于：

- 获取游戏 Release、模组市场索引、模组详情/README；
- 下载游戏/模组/整合包/启动器更新；
- 诊断里的日志上报队列（用于页面日志采集，不是存档上传）。

启动器不会主动上传你的存档内容。

### Q57. 想彻底重置启动器怎么办？

先备份，再二选一：

- 只重置配置：删除 `launcher-versions.json` 后重新扫描；
- 完全重置：删除整个 `DoL/` 数据目录（或清除应用数据），重新开始。

## 11. 桌面端与 Android 端差异

### Q58. 为什么 Android 端有些桌面功能没有？

受系统能力限制，目前未实现或降级的功能：

| 功能 | 现状 |
| --- | --- |
| 添加已有版本目录 | 未实现（需 SAF 目录树），请导入 zip |
| 自定义启动预取顺序 | 未实现，Android 仅「同时预取 / 不预取」 |
| 文件夹选择器 | 使用系统文件选择/SAF |
| 同时运行多个版本 | 同一时间保留一个游戏 WebView |
| 剧情长图导出 | 超高图会缩放，失败时降级 JSON |
| file:// 版本完整能力 | 受 WebView 本地文件限制 |

### Q59. 「页面」和「界面」在本文里有什么区别？

沿用启动器的界面术语：

- **页面**：主界面左侧栏切换的右侧内嵌面板（版本管理、下载中心、备份、剧情、诊断）；
- **界面**：通过导航压栈打开的原生页面，上方有标题栏和返回按钮（如版本详情、模组管理、存档助手、长文本查看）。
